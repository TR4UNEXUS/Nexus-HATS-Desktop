Publishing Windows app updates

Update repository: https://github.com/TR4UNEXUS/Nexus-HATS-Desktop

1. Increase Version in source/Hats.WinUI/Hats.WinUI.csproj and build with
   build.ps1. Keep the existing Product and AssemblyName values.
2. Create a published, stable GitHub release. The tag must match the EXE's
   embedded version, for example windows-v1.0.1 or v1.0.1.
   windows-v1.0.1 keeps Windows app tags distinct from other releases.
3. Attach this exact file directly as a release asset:
     Nexus-HATS-Desktop.x64.exe
   Attaching only a ZIP does not provide a self-update executable.
4. Wait until GitHub reports the asset uploaded with a SHA-256 digest.
   Drafts and prereleases are deliberately not offered to users.
5. In an older updater-enabled app, use Options > Check for app updates.

The updater chooses the highest stable version with the exact Windows EXE
asset. The GitHub tag, file version and product identity must agree. A new
version must be greater than the installed version. Publish a new version
instead of silently replacing an existing version's executable.

This local build does not publish or modify any GitHub release. Existing
users must download Nexus HATS Desktop once, then it can deliver later
published versions. No GitHub token or account sign-in is needed to update.

Validation used for this build:
  test.ps1 -AppExe <path-to-built-exe> -LiveApp

Implementation references:
https://docs.github.com/en/rest/releases/releases#list-releases
https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace
